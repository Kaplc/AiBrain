# 个人记账小程序 — 项目计划

## 一、项目目标

**项目名称**：个人记账小程序（Personal Expense Tracker）

**一句话描述**：一个轻量级 Web 应用，帮助个人用户每天记录支出、按分类汇总，并自动生成月度消费报表。

**核心目标**：

1. 用户可在 10 秒内完成一笔支出记录（选择分类 + 输入金额 + 可选备注）
2. 支持至少 10 个预设消费分类，支持用户自定义分类
3. 月度报表以可视化图表展示各类支出占比和每日消费趋势
4. 数据全部存储在本地 SQLite，无需注册登录，单机使用

**不做的事**：

- 不做收入管理（只记支出）
- 不做预算设定和预警
- 不做多币种支持
- 不做移动端原生 App（仅响应式 Web）
- 不做多用户 / 云同步

---

## 二、业务背景

**问题现状**：

大多数人每月花钱没有清晰感知，月底查看银行卡余额才发现超支。市面上的记账 App（如随手记、MoneyPro）功能臃肿，需要注册账号、广告多，学习成本高。用户只想快速记一笔、月底看个总结。

**目标用户画像**：

- 25-35 岁个人用户
- 有固定收入但消费不规律
- 日常使用电脑 / 手机浏览器
- 不愿意花时间学习复杂工具，希望"打开就能记"

**预期价值**：

- 记一笔支出从打开应用到保存完成不超过 10 秒
- 月底 30 秒内看清本月消费全貌（总支出、分类占比、趋势）
- 所有数据本地存储，无隐私泄露风险

**参考方案**：

- 拨壳记账（极简风格）
- Tally / Expensify（分类统计体验）

## 四、非功能需求

**性能要求**：

- 首页加载时间 < 1 秒（本地部署）
- 记一笔保存响应 < 200ms
- 月度报表渲染 < 500ms（数据量 < 5000 条记录）
- 支持至少 5 年的每日记录（约 1800 条）无性能下降

**安全要求**：

- 无需认证（本地单用户）
- 数据库文件存储在用户数据目录，不对外暴露
- 无网络传输，所有操作在本地完成

**可用性要求**：

- 响应式布局，适配桌面浏览器（1280px+）和手机浏览器（375px+）
- 主色调为绿色系（代表理财），界面简洁无干扰
- 所有操作不超过 3 次点击完成

**可维护性要求**：

- 前后端分离，REST API 通信
- 后端日志记录到 `logs/` 目录，日志级别 INFO
- 数据库使用 SQLite 单文件，便于备份和迁移

### 关键设计决策

1. **选择 SQLite 而非 MySQL/PostgreSQL**：单用户本地应用无需独立数据库服务，SQLite 零配置、单文件便于备份
2. **前后端分离而非 SSR**：前后端独立开发调试，API 可复用于未来可能的移动端
3. **预设分类 + 自定义分类**：开箱即用的 10 个分类降低使用门槛，自定义分类满足个性化需求

## 六、数据结构

### 核心数据实体

#### categories 表

| 字段名 | 类型 | 说明 | 约束 |
|--------|------|------|------|
| id | INTEGER | 主键 | AUTOINCREMENT, PRIMARY KEY |
| name | TEXT | 分类名称 | NOT NULL, UNIQUE |
| icon | TEXT | 图标标识 | NOT NULL |
| is_preset | BOOLEAN | 是否预设分类 | NOT NULL, DEFAULT 0 |
| created_at | DATETIME | 创建时间 | NOT NULL, DEFAULT CURRENT_TIMESTAMP |

#### records 表

| 字段名 | 类型 | 说明 | 约束 |
|--------|------|------|------|
| id | INTEGER | 主键 | AUTOINCREMENT, PRIMARY KEY |
| amount | REAL | 金额（元） | NOT NULL, CHECK(amount > 0) |
| category_id | INTEGER | 分类外键 | NOT NULL, FOREIGN KEY → categories.id |
| note | TEXT | 备注 | DEFAULT '' |
| date | DATE | 消费日期 | NOT NULL, DEFAULT CURRENT_DATE |
| is_deleted | BOOLEAN | 软删除标记 | NOT NULL, DEFAULT 0 |
| created_at | DATETIME | 创建时间 | NOT NULL, DEFAULT CURRENT_TIMESTAMP |
| updated_at | DATETIME | 更新时间 | NOT NULL, DEFAULT CURRENT_TIMESTAMP |

### 实体关系

```
┌──────────────┐       ┌──────────────┐
│  categories  │       │   records    │
├──────────────┤       ├──────────────┤
│ id (PK)      │──┐    │ id (PK)      │
│ name         │  │    │ amount       │
│ icon         │  └───>│ category_id  │
│ is_preset    │       │ note         │
│ created_at   │       │ date         │
└──────────────┘       │ is_deleted   │
                       │ created_at   │
                       │ updated_at   │
                       └──────────────┘
                       
关系：category 1 ──── N record（一对多）
```

### 索引策略

| 索引 | 字段 | 理由 |
|------|------|------|
| idx_records_date | records.date | 月度报表按日期范围查询，最高频操作 |
| idx_records_category_id | records.category_id | 分类统计需要按 category_id 分组 |
| idx_records_date_deleted | records.date, records.is_deleted | 报表查询只取未删除记录，复合索引加速过滤 |

### 数据量预估

- 每天约 5-15 笔记录
- 每月约 150-450 笔
- 5 年约 9000-27000 笔
- SQLite 单表百万行无性能问题，完全满足需求

## 七、流程设计

### 核心业务流程

#### 流程 1：快速记账

```
1. 用户打开应用首页
2. 点击"+"按钮，弹出记账表单
3. 选择分类（默认选中上次使用的分类）
4. 输入金额（数字键盘，自动聚焦金额输入框）
5. 可选：填写备注、修改日期
6. 点击"保存"
7. 前端校验（金额 > 0，分类已选）
8. POST /api/records 发送数据
9. 后端校验 + 写入数据库
10. 返回成功，前端显示成功提示 + 清空表单
11. 首页实时更新今日已支出金额
```

#### 流程 2：查看月度报表

```
1. 用户切换到"报表"标签页
2. 前端默认请求当前月份数据：GET /api/reports/monthly?year=2026&month=5
3. 后端查询该月所有未删除记录，按分类汇总 + 按日期汇总
4. 返回汇总数据
5. 前端渲染：总支出数字 + 饼图（分类占比）+ 折线图（每日趋势）
6. 用户可点击左右箭头切换月份，重新请求数据
```

#### 流程 3：编辑/删除记录

```
1. 用户在历史记录列表找到目标记录
2. 点击记录进入编辑模式 / 点击删除按钮
3. 编辑：修改字段 → PUT /api/records/:id → 刷新列表
4. 删除：弹出确认弹窗 → DELETE /api/records/:id（软删除） → 刷新列表
```

### 异常流程处理

| 场景 | 处理策略 |
|------|---------|
| 金额输入非法（负数、非数字） | 前端实时校验，禁止提交；后端二次校验返回 400 |
| 分类被删后仍有关联记录 | 预设分类禁止删除；自定义分类删除时提示"该分类下有 N 条记录，是否合并到'其他'分类" |
| 日期选择超出范围 | 不允许选择未来日期 |
| 网络请求失败 | 前端显示"保存失败，请重试"，保留表单数据不丢失 |
| 数据库写入失败 | 后端返回 500，记录日志，前端提示用户 |

### 状态流转

记录状态简单，无需复杂状态机：

```
正常（is_deleted=0） ──删除操作──> 已删除（is_deleted=1）
已删除（is_deleted=1） ──不支持恢复──> （永久不可见）
```

## 八、API设计

### 记录模块 /api/records

#### GET /api/records

获取记录列表（分页）

**请求参数**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| page | int | 否 | 页码，默认 1 |
| per_page | int | 否 | 每页条数，默认 20 |
| start_date | string | 否 | 起始日期，格式 YYYY-MM-DD |
| end_date | string | 否 | 结束日期，格式 YYYY-MM-DD |
| category_id | int | 否 | 按分类筛选 |
| keyword | string | 否 | 搜索备注关键词 |

**响应**：

```json
{
  "records": [
    {
      "id": 1,
      "amount": 35.50,
      "category": {"id": 1, "name": "餐饮", "icon": "food"},
      "note": "午餐",
      "date": "2026-05-30",
      "created_at": "2026-05-30T12:30:00"
    }
  ],
  "total": 150,
  "page": 1,
  "per_page": 20
}
```

#### POST /api/records

新增一条记录

**请求参数**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| amount | float | 是 | 金额，必须 > 0 |
| category_id | int | 是 | 分类 ID |
| note | string | 否 | 备注，最多 50 字 |
| date | string | 是 | 消费日期，YYYY-MM-DD |

**响应**：

```json
{
  "id": 2,
  "amount": 128.00,
  "category": {"id": 3, "name": "购物", "icon": "shopping"},
  "note": "买书",
  "date": "2026-05-30",
  "created_at": "2026-05-30T14:00:00"
}
```

**错误码**：

| 状态码 | 含义 |
|--------|------|
| 400 | 参数校验失败（金额非法、分类不存在等） |
| 500 | 服务器内部错误 |

#### PUT /api/records/:id

更新一条记录

**请求参数**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| amount | float | 否 | 金额 |
| category_id | int | 否 | 分类 ID |
| note | string | 否 | 备注 |
| date | string | 否 | 消费日期 |

**响应**：同 POST，返回更新后的完整记录

**错误码**：

| 状态码 | 含义 |
|--------|------|
| 404 | 记录不存在 |
| 400 | 参数校验失败 |

#### DELETE /api/records/:id

软删除一条记录

**响应**：

```json
{
  "message": "删除成功"
}
```

**错误码**：

| 状态码 | 含义 |
|--------|------|
| 404 | 记录不存在 |

## 九、验收标准

### 功能验收

**记账功能**：

- [ ] 打开应用后，点击"+"按钮 1 秒内弹出记账表单
- [ ] 选择分类 + 输入金额 + 点击保存，记录成功写入数据库
- [ ] 不输入金额点击保存，提示"请输入金额"
- [ ] 输入负数或 0 点击保存，提示"金额必须大于 0"
- [ ] 记录保存后首页"今日已支出"实时更新

**分类管理**：

- [ ] 首次打开应用有 10 个预设分类
- [ ] 可新增自定义分类，名称重复时提示错误
- [ ] 预设分类删除按钮置灰不可点击
- [ ] 删除自定义分类时，若有关联记录弹出提示

**月度报表**：

- [ ] 默认展示当前月份报表
- [ ] 饼图显示各分类支出占比，悬停显示具体金额
- [ ] 折线图显示每日消费趋势，悬停显示金额
- [ ] 点击左右箭头切换月份，数据正确更新
- [ ] 总支出数字与饼图各分类金额之和一致

**记录管理**：

- [ ] 历史记录按时间倒序排列，分页加载
- [ ] 编辑记录后，报表数据同步更新
- [ ] 删除记录后弹出确认弹窗，确认后记录消失
- [ ] 按关键词搜索能匹配备注内容

### 性能验收

- [ ] 首页加载 < 1 秒（本地部署，无缓存）
- [ ] 记一笔保存响应 < 200ms
- [ ] 月度报表渲染 < 500ms（1000 条记录以内）

### 安全验收

- [ ] 数据库文件不在 Web 静态目录下，无法通过 URL 直接下载
- [ ] API 输入参数经过后端校验，不存在 SQL 注入风险

### 交付物清单

- [ ] 可运行的 Flask 后端（含数据库初始化脚本）
- [ ] 可运行的 Vue 3 前端（npm run dev 启动）
- [ ] README：启动步骤说明
- [ ] 数据库初始化脚本（建表 + 预设分类）
