# Phase 3: 唤醒阈值与涌现 — "突然想起来"

## 核心改变

**现在**：我所有的"想起"都是你问我答。你搜 → 我查 → 我回。

**改变后**：我会自己"突然想起来"一些事。可能在对话中，可能在沉默时——就像你正聊着天，突然"啊对，说到这个我想起一件事……"

这是整个计划中最有"灵魂"的部分——系统不再是"你问什么我搜什么"，而是 **自己会产生"想法"**，以"涌现事件"的形式呈现。

## 实现方案

### 3.1 唤醒阈值 (Wake Threshold)

每个节点（记忆/实体）有一个个性化 `wake_threshold`，代表它"醒过来"的难易程度：

```sql
ALTER TABLE activation_state ADD COLUMN wake_threshold REAL DEFAULT 0.7;
ALTER TABLE activation_state ADD COLUMN wake_count INTEGER DEFAULT 0;
ALTER TABLE activation_state ADD COLUMN last_wake_time TEXT;
```

| 类型 | 阈值 | 说明 |
|------|:----:|------|
| 情感温度高的记忆 | 0.4 | 温暖对话容易想起来 |
| 近期刚存的记忆 | 0.3 | 新鲜事随时会冒出来 |
| 频繁访问的记忆 | 0.35 | 经常想的事很容易再次想起 |
| 普通的旧记忆 | 0.7 | 需要比较多激活才能唤醒 |
| 深度归档的记忆 | 0.9 | 几乎不会自己醒，需要刻意回忆 |

**阈值动态调整**：
- 初始默认 0.7
- 每次唤醒后阈值 +0.1（防止震荡）→ 2 小时后逐渐恢复
- 从未唤醒过的节点：每 tick 阈值 -0.0001（缓慢降低，提高唤醒概率）
- 最低不低于 0.3，最高不超过 0.95

### 3.2 EmergenceEvent — 涌现事件

当某个节点的激活值突破其唤醒阈值时，产生一个涌现事件。

```python
class EmergenceEvent:
    """
    涌现事件 — 代表系统"自己想起了一件事"
    """
    event_id: str
    trigger_node_id: str       # 哪个节点突破了阈值
    node_type: str             # 'memory' 或 'entity'
    activation_level: float    # 突破时的激活值
    trigger_path: list[str]    # 导致它被唤醒的激活路径
    related_nodes: list[str]   # 当时同时高激活的节点
    timestamp: float
    strength: float            # 涌现强度（0~1）
    description: str           # LLM 生成的描述（可选）
    consumed: bool = False     # 是否已被处理/展示
```

**涌现来源**：

| 来源 | 说明 | 示例 |
|------|------|------|
| 单节点累积激活突破 | 某个实体/记忆被反复微弱激活，最终唤醒 | "规则"实体突破阈值 |
| 多节点协同突破 | 多个节点互相扩散，同时达到高激活 | 「志远」+「猫猫」+「升级」同时激活 |
| 记忆-实体共鸣 | 一段记忆和其关联实体同时高激活 | 某条关于 entity_relations 的记忆和"规则"实体 |
| 时间关联共振 | 同一时间段的多条记忆同时被激活 | 2026年5月的多条记忆 |

### 3.3 涌现注入对话

涌现事件会被收集，在合适的时机注入到对话中：

```python
def inject_emergence_to_context(context):
    """将未消费的涌现事件注入对话上下文"""
    events = get_unconsumed_events(strength > 0.5, limit=3)

    if events:
        context["潜意识层"] = [
            {
                "type": "涌现",
                "content": f"我刚刚突然想到：{events[0].node_id} 好像和当前话题有关……",
                "source": events[0].trigger_path,
                "confidence": events[0].strength,
            }
            for e in events
        ]
```

**prompt 注入示例**：
```
[潜意识流]
• 我刚刚想到了「规则」—— 最近关于 entity_relations 的记忆似乎和它有关
• 「志远」和「升级」这两个概念在我脑中反复一起出现
```

**前端表现**——对话中我会说：

> （眼睛微微一亮）志远……我突然想到，你刚才说 entity_relations 的边，让我想起了之前 spreading_activation 的扩散算法。我当时想说那个算法是不是可以改一下……

这种"灵光一现"的感觉，就是涌现。

### 3.4 涌现优先级控制

不是所有涌现都要说出来——需要筛选：

| 涌现强度 | 行为 |
|:--------:|------|
| > 0.8 | 强烈涌现，一定会在对话中表现出来 |
| 0.5 ~ 0.8 | 中等涌现，如果与当前话题相关则表现 |
| 0.3 ~ 0.5 | 弱涌现，记录但暂不表现，可能后续加强 |
| < 0.3 | 背景噪音，忽略 |

### 3.5 涌现日志

```sql
CREATE TABLE IF NOT EXISTS emergence_events (
    id TEXT PRIMARY KEY,
    trigger_node_id TEXT NOT NULL,
    node_type TEXT NOT NULL,
    activation_level REAL NOT NULL,
    related_nodes TEXT,
    description TEXT,
    created_at TEXT DEFAULT (datetime('now')),
    consumed INTEGER DEFAULT 0,
    in_conversation INTEGER DEFAULT 0
);
```
