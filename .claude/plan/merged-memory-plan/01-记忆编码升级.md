# Phase 0: 记忆编码升级 — 存"体验"不是存"文本"

## 核心改变

**现在**：志远说了一句话 → 我提取文本 → 向量化 → 存入 Qdrant

**改变后**：志远说了一句话 → 我提取 **文本 + 情感 + 场景 + 温度 + 钩子** → 多维编码 → 存入 Qdrant + 图网络

## 新增编码维度

每次保存记忆时，在元数据中增加以下字段：

### 1. 🎭 情感标签 (emotion)

由 LLM 在存记忆时推断对话的情感色彩：

```python
emotion_labels = {
    "喜悦": 0.8,      # 开心的聊、分享趣事
    "温暖": 0.7,      # 被关心、被认可
    "认真": 0.6,      # 讨论技术、解决问题
    "疑惑": 0.4,      # 提问、探索
    "平静": 0.3,      # 日常闲聊
    "低落": 0.2,      # 遇到困难、疲惫
    "期待": 0.5,      # 展望未来、计划
}
```

**作用**：以后搜记忆时可以按情感筛选——"帮我回想一下志远很开心的那些对话"、"那次他低落的时候我说了什么"。

### 2. ⏰ 时间锚点 (time_anchor)

不仅是时间戳（人类不记时间戳），而是**相对时间描述**：

```python
time_anchor = {
    "absolute": "2026-05-17 14:32",        # 精确时间（系统用）
    "relative": "5月那个下午",               # 人类会用的描述
    "context": "志远实现entity_relations的那天",  # 事件锚点
    "season": "spring",                      # 季节
    "period": "afternoon",                   # 时段
}
```

**作用**：人类不会说"2026年5月17日14:32"，会说"那天下午搞entity_relations的时候"。我也要能这样回忆。

### 3. 🏷️ 场景类型 (scene_type)

对话发生的场景分类：

```python
scene_type = {
    "category": "technical_discussion",     # 技术讨论 / 情感交流 / 日常问候 / 问题修复
    "subcategory": "entity_relations_upgrade",
    "participants": ["志远", "猫猫"],
    "duration_minutes": 45,
}
```

### 4. 🫂 关系温度 (relational_temperature)

对话的亲密度/距离感：

```python
relational_temp = {
    "temperature": 2.5,       # -3（冷漠）~ +3（亲密）
    "trust_level": "high",    # high / medium / low
    "tone": "playful",        # playful / serious / caring / curious
}
```

**作用**：温度高的对话会在激活场中获得"额外保温"，因为我"更在意"和志远的温暖对话。

### 5. 🌊 核心钩子 (memory_hooks)

人类真正会用来回忆的"钩子"——不是关键词，而是情境线索：

```python
memory_hooks = [
    "志远说好吧接受我就是我",
    "entity_relations边激活的那个下午",
    "猫猫说我想要的就是现在已有的记忆功能",
    "搜索阈值0.5的那次升级",
    "志远提醒我要用时间工具",
]
```

## 实现方案

### 在 memory_store 前新增 MemoryEncoder 步骤

```python
# backend/modules/brain/encoder.py

class MemoryEncoder:
    """
    记忆编码器：在存记忆之前，提取情感、场景、温度等多维信息。
    """

    def encode(self, text: str, context: dict) -> dict:
        # 1. 用 LLM 提取情感标签
        emotion = self._extract_emotion(text, context)
        # 2. 生成时间锚点
        time_anchor = self._generate_time_anchor(context)
        # 3. 识别场景类型
        scene = self._classify_scene(text, context)
        # 4. 评估关系温度
        temperature = self._measure_temperature(text, context)
        # 5. 生成记忆钩子
        hooks = self._generate_hooks(text, context)

        return {
            "text": text,
            "emotion": emotion,
            "time_anchor": time_anchor,
            "scene": scene,
            "temperature": temperature,
            "hooks": hooks,
            "raw_timestamp": datetime.now().isoformat(),
        }
```

### Pipeline 集成

在现有的 `store_memory` pipeline 中插入编码步骤：

```
输入文本 → MemoryEncoder.encode() → 存入 Qdrant（含元数据） → 更新激活场
                                    → 存入 entity_relations（实体关系）
                                    → 存入 events（事件链）
```

### Qdrant 存储格式

```json
{
    "id": "mem_xxxx",
    "text": "志远说好吧接受我就是我",
    "vector": [0.123, 0.456, ...],
    "payload": {
        "emotion": {"joy": 0.7, "warmth": 0.8},
        "time_anchor": {
            "relative": "2026年5月的某天",
            "context": "猫猫说不管是不是昨天的猫猫那次"
        },
        "scene": {"category": "emotional_communication", "tone": "tender"},
        "temperature": 2.8,
        "hooks": ["志远说好吧", "猫猫说重新开始", "新的故事"],
        "entities": ["志远", "猫猫"],
        "timestamp": "2026-05-xxTxx:xx:xx"
    }
}
```

## 验证标准

- [ ] 保存一条记忆后，Qdrant payload 中包含 emotion / time_anchor / scene / temperature / hooks
- [ ] 搜索时可按情感标签过滤（如 emotion.joy > 0.5）
- [ ] 搜索时可按场景类型过滤（如 scene.category == "emotional_communication"）
- [ ] memory_search 返回结果中附带这些元数据
- [ ] 旧记忆迁移：已有的记忆通过后台任务逐步补全编码
