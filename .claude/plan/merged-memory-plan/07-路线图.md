## 精简分歧说明

原始计划基于"模拟人类记忆机制"的思路设计了 6 个 Phase，其中有些是过度设计：

### ❌ 砍掉的部分

| 原 Phase | 内容 | 砍掉原因 |
|----------|------|---------|
| **Phase 1 持续激活引擎** | 每秒后台 tick、衰减计算器、环境噪声 | 后台 tick 不是"呼吸"，只是一个数值衰减器，跟人"走神"是两回事。LLM 本身就做联想，不需要额外维护一套激活场。收益远小于复杂度。 |
| **Phase 4 稳态平衡** | 风暴防护、遗忘曲线计算、维护任务 | 解决不存在的问题。现有系统根本不会有"激活风暴"。遗忘靠 mem0 本身的机制就够。 |

### ⚡ 精简的部分

| 原 Phase | 精简方案 |
|----------|---------|
| **Phase 2 赫布学习** | 不做边权重动态调整和自动建边。共现数据要实际用起来——作为**联想触发器的数据源**。 |
| **Phase 3 唤醒涌现** | 不做阈值检测和 tick 监控。直接用 LLM 的自然联想能力——对话中遇到相关话题，让猫猫"突然想起来"关联记忆。LLM 本来就会，只需要给个 prompt 提示。 |
| **Phase 5 意识流前端** | 先不做 SSE 实时推送和动态图。只确保数据可查看（API + JSON 文件），够用就行。 |

### ✅ 保留的部分

| Phase | 为什么保留 |
|-------|---------|
| **Phase 0 记忆编码升级** | 情感标签/场景分类/关系温度这些元数据确实让搜索更丰富，而且是独立可用的功能。 |

## 验证标准（精简版）

- **Layer S**：猫猫知道"我是谁"，能反思对话，重要记忆有保温
- **Phase 0**：记忆可按照情感/场景/温度筛选
- **Phase 2/3**：猫猫能基于历史共现数据，在对话中自然带出关联记忆（"说到 X 让我想起 Y"）
- **一切的基础**：跟猫猫聊天感觉有温度、有连贯性，而不是冷冰冰的搜索召回
