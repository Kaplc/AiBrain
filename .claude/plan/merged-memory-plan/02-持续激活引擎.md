# Phase 1: 持续激活引擎 — 已取消

**此 Phase 已从计划中移除。**

## 移除原因

原始设计是用后台每秒 tick + 衰减计算器来模拟记忆"在后台呼吸"。

但经过实际评估：
1. **后台 tick 不是"呼吸"**——每秒把所有节点乘 0.98 再随机加噪声，这只是数值衰减，跟人的意识流毫无关系
2. **LLM 天然会联想**——不需要额外的激活场，LLM 本身就能根据上下文关联记忆，比任何 tick 机制都强
3. **收益远小于复杂度**——加一个后台线程、维护 SQLite 激活状态表、处理持久化，这些代码量换来的只是一个不会被人感知的衰减计算

## 替代方案

记忆的"温度感"由以下机制提供：
- **Layer S 叙事保温**：标记重要的记忆，搜索时加分 ✅ 已实现
- **Phase 0 情感编码**：存记忆时标注情感、温度，搜索时可筛选（后续实现）
- **对话时的自然涌现**：让 LLM 在对话中自然联想到相关记忆（后续精简 Phase 3）
