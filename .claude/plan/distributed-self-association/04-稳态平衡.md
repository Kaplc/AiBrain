# Phase 4: 稳态平衡 — 防止失忆与过载

## 核心思想

> 稳态平衡机制：避免系统过度激活或失忆。

就像生物神经系统不能一直兴奋也不能完全休眠一样，
分布式自关联系统需要**自我调节**的能力。

## 实现方案

### 4.1 全局激活预算

```python
class ActivationBudget:
    """
    全局激活预算 —— 限制系统中同时高激活的节点数量。
    
    规则：
    1. 系统总激活能量 = 节点数 * 0.3（平均每个节点 0.3）
    2. 所有节点的激活值之和不能超过总预算
    3. 当注入新激活时，如果超出预算，所有激活值按比例压缩
    4. 压缩公式: new_act = old_act * (budget / total_activation)
    
    效果：
    - 防止少数节点垄断所有激活
    - 新输入会"挤占"旧激活的位置
    - 系统自然地"忘记"不重要的内容
    """
    
    BUDGET_PER_NODE = 0.3
    
    def compress_if_needed(self):
        total = sum(self._activations.values())
        budget = len(self._activations) * self.BUDGET_PER_NODE
        if total > budget:
            scale = budget / total
            for node_id in self._activations:
                self._activations[node_id] *= scale
```

### 4.2 记忆"遗忘"机制

不是真的删除记忆，而是**降低其在激活场中的可唤醒性**。

```python
class ForgettingCurve:
    """
    艾宾浩斯遗忘曲线 —— 长期不访问的记忆唤醒阈值逐渐升高。
    
    公式：可唤醒性 = e^(-days_since_last_access / half_life)
    
    层级：
    - 近期记忆（7天内）：half_life = 30 天，几乎不衰减
    - 中期记忆（30天内）：half_life = 14 天，缓慢衰减
    - 远期记忆（>30天）：half_life = 7 天，加速衰减
    - 核心记忆（被多次唤醒的）：half_life = 90 天，几乎不遗忘
    
    当可唤醒性 < 0.1 时，节点进入"休眠态"：
    - 不再参与环境噪声注入
    - 激活扩散时不再传播给它
    - 但不会从数据库中删除（可以通过精确搜索找回）
    """
```

### 4.4 激活风暴防护

```python
class StormProtection:
    """
    防止激活值在短时间内异常飙升（如批量导入记忆时）。
    
    检测：
    - 单 tick 激活增长 > 200% → 触发抑制
    - 5 tick 内总激活增长 > 500% → 触发抑制
    
    抑制方式：
    - 强制将所有激活值乘以 0.5
    - 临时提高全局衰减率（0.98 → 0.92）
    - 记录风暴事件到日志
    - 风暴后逐渐恢复（5 tick 内回归正常）
    """
```

### 4.5 定期维护任务

```python
class MaintenanceTask:
    """
    每 24 小时执行一次：
    1. 清理 activation_state 中长期休眠（可唤醒性 < 0.05 且 access_count=0）的节点
       （只清理激活状态，不清理记忆和图边）
    2. 重新计算所有节点的 half_life
    3. 压缩 emergent_relations 中从未"转正"且 co_activation_count < 3 的记录
    4. 归档 7 天前的 emergence_events（标记已处理）
    5. 重建实体计数（已有 rebuild_entity_counts）
    """
```
