# Phase 3: 唤醒阈值与涌现 — 让关联"自己冒出来"

## 核心思想

> 当某几个节点之间的微弱激活互相加强，直到突破阈值——顿悟就发生了。
> 这个过程不需要一个专门的"后台小人"去监控和整理——它是网络的自然动力学。

这是整个计划中最有"灵魂"的部分——系统不再是"你问什么我搜什么"，
而是**自己会产生"想法"**，以"涌现事件"的形式呈现。

## 实现方案

### 3.1 唤醒阈值机制

每个节点（记忆/实体）除了激活值，还多一个**个性化阈值**：

```sql
ALTER TABLE activation_state ADD COLUMN wake_threshold REAL DEFAULT 0.7;
ALTER TABLE activation_state ADD COLUMN wake_count INTEGER DEFAULT 0;
ALTER TABLE activation_state ADD COLUMN last_wake_time TEXT;
```

**阈值动态调整**：
- 初始默认 0.7（偏高，避免误唤醒）
- 每次唤醒后阈值 +0.1（防止震荡）→ 2 小时后逐渐恢复
- 从未唤醒过的节点：每 tick 阈值 -0.0001（缓慢降低，提高唤醒概率）
- 最低不低于 0.3，最高不超过 0.95

### 3.2 EmergenceEvent — 涌现事件

当某个节点的激活值突破其唤醒阈值时，产生一个涌现事件。

```python
@dataclass
class EmergenceEvent:
    event_id: str
    trigger_node_id: str       # 哪个节点突破了阈值
    node_type: str             # 'memory' 或 'entity'
    activation_level: float    # 突破时的激活值
    related_nodes: list[str]   # 当时同时高激活的节点
    timestamp: float
    description: str           # LLM 生成的描述（可选）
    consumed: bool = False     # 是否已被处理/展示
```

**涌现来源**：

| 来源 | 说明 | 示例 |
|------|------|------|
| 单节点累积激活突破 | 某个实体/记忆被反复微弱激活，最终唤醒 | "规则"实体突破阈值 |
| 多节点协同突破 | 多个节点互相扩散，同时达到高激活 | 「志远」+「猫猫」+「升级」同时激活 |
| 记忆-实体共鸣 | 一段记忆和其关联实体同时高激活 | 某条关于 entity_relations 的记忆和"规则"实体 |
| 时间关联共振 | 同一时间段的多条记忆同时被激活 | 2026年5月的多条记忆 |

### 3.3 涌现处理管线

```python
class EmergenceProcessor:
    """
    当涌现事件发生时：
    1. 记录到 emergence_events 表
    2. 可选：调 LLM 生成一句话描述（"我好像想起了什么..."）
    3. 将涌现事件的摘要注入到短期工作记忆
    4. 在工作记忆中表现为"自发联想到"的上下文
    """
    
    async def process_emergence(self, event: EmergenceEvent):
        # 记录
        self._record_event(event)
        # 如果激活水平足够高，生成自然语言描述
        if event.activation_level > 0.8:
            description = await self._generate_description(event)
            # 将描述注入 subconscious（潜意识层）
            self._inject_to_subconscious(description)
```

### 3.4 短期工作记忆整合

当前系统有 `workmemory` 目录，但潜意识层(`subconscious.py`)只有 716 字节。

```python
# backend/modules/brain/activation/consciousness.py

class ConsciousnessStream:
    """
    意识流 —— 整合涌现事件到对话上下文中。
    
    工作方式：
    1. 维护一个环形缓冲区（最近 10 个涌现事件）
    2. 在每次对话轮次开始时，检查缓冲区
    3. 如果有高置信度的涌现事件（activation > 0.85）：
       - 以"我刚刚想到..."的形式注入 system prompt
    4. 低置信度事件只记录不展示
    """
```

**prompt 注入示例**：
```
[潜意识流]
• 我刚刚想到了「规则」—— 最近关于 entity_relations 的记忆似乎和它有关
• 「志远」和「升级」这两个概念在我脑中反复一起出现
```

### 3.5 涌现日志

```sql
CREATE TABLE IF NOT EXISTS emergence_events (
    id TEXT PRIMARY KEY,
    trigger_node_id TEXT NOT NULL,
    node_type TEXT NOT NULL,
    activation_level REAL NOT NULL,
    related_nodes TEXT,           -- JSON array
    description TEXT,
    created_at TEXT DEFAULT (datetime('now')),
    consumed INTEGER DEFAULT 0,
    in_conversation INTEGER DEFAULT 0  -- 是否在对话中展示过
);
```

- [ ] 高激活涌现事件（>0.85）成功注入到对话上下文中
