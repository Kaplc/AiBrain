# Phase 2: 赫布学习 — "Fire Together, Wire Together"

## 核心思想

> 同时激活的节点之间的连接会加强。你经常走的小路会越来越清晰。

当前的 `entity_relations` 和 `memory_relations` 是**静态**的——边一旦建立，权重不变。
赫布学习让系统**自己强化常用路径、弱化废弃路径**。

## 实现方案

### 2.1 边权重表扩展

当前 `memory_relations` 已经有 `weight` 字段，但从未动态更新。
`typed_entity_relations` 也有 `weight`，由 LLM 初始设定后不变。

新增字段和机制：

```sql
-- 给现有表追加统计字段
ALTER TABLE memory_relations ADD COLUMN co_activation_count INTEGER DEFAULT 1;
ALTER TABLE memory_relations ADD COLUMN last_co_activated TEXT;

ALTER TABLE typed_entity_relations ADD COLUMN co_activation_count INTEGER DEFAULT 1;
ALTER TABLE typed_entity_relations ADD COLUMN last_co_activated TEXT;
```

### 2.2 HebbianPlasticity — 赫布可塑性模块

```python
# backend/modules/brain/activation/hebbian.py

class HebbianPlasticity:
    """
    赫布可塑性：当两个节点同时处于高激活状态时，加强它们之间的连接。
    
    规则：
    1. 每 tick 检查所有激活值 > 0.3 的节点对
    2. 如果两个节点在图中有边，且同时激活 > 阈值：
       - weight += 0.05 * (共同激活度)
       - co_activation_count += 1
       - 权重上限 2.0
    3. 如果两个节点没有边，但频繁同时激活：
       - 自动在 entity_relations 中创建新边（初始 weight=0.3）
       - 记录到新表 emergent_relations
    """
    
    CO_ACT_THRESHOLD = 0.3       # 同时激活阈值
    WEIGHT_INCREMENT = 0.05      # 每次加强量
    MAX_WEIGHT = 2.0             # 权重上限
    MIN_WEIGHT = 0.1             # 权重下限（低于此值可能自动裁边）
    NEW_EDGE_THRESHOLD = 5       # 同时激活多少次后创建新边
    NEW_EDGE_INIT_WEIGHT = 0.3   # 新边的初始权重
```

### 2.3 记忆-记忆边动态强化

当前 `memory_relations` 的边只在 `_link_memory_to_memory()` 创建（新建记忆时通过共享实体建边）。
赫布学习在此基础上增加：

```python
def reinforce_memory_edge(self, mem_a: str, mem_b: str, co_activation: float):
    """加强或创建记忆-记忆边"""
    existing = self._exec(
        "SELECT weight FROM memory_relations WHERE from_mem=? AND to_mem=?",
        (mem_a, mem_b)
    )
    if existing:
        new_weight = min(existing[0][0] + 0.05 * co_activation, 2.0)
        self._exec(
            "UPDATE memory_relations SET weight=?, co_activation_count=co_activation_count+1, "
            "last_co_activated=datetime('now') WHERE from_mem=? AND to_mem=?",
            (new_weight, mem_a, mem_b)
        )
    else:
        # 创建新的记忆-记忆边（弱连接起点）
        self._exec(
            "INSERT OR IGNORE INTO memory_relations (from_mem, to_mem, via_entity, weight, co_activation_count) "
            "VALUES (?, ?, '__hebbian__', ?, 1)",
            (mem_a, mem_b, 0.3)
        )
```

### 2.4 实体-实体边涌现

这是最有趣的——**系统自己"发现"两个实体应该有关系**。

```sql
CREATE TABLE IF NOT EXISTS emergent_relations (
    from_entity TEXT NOT NULL,
    to_entity TEXT NOT NULL,
    co_activation_count INTEGER DEFAULT 1,
    first_observed TEXT DEFAULT (datetime('now')),
    last_observed TEXT DEFAULT (datetime('now')),
    strength REAL DEFAULT 0.3,
    PRIMARY KEY (from_entity, to_entity)
);
```

逻辑流程：
1. 每 tick，找出所有激活值 > 0.3 的实体节点对
2. 如果它们已有 `entity_relations` 边 → 强化现有边
3. 如果它们没有边 → 在 `emergent_relations` 中计数
4. 当 `co_activation_count >= 5` → 自动在 `entity_relations` 中建边
5. 同时在 `emergent_relations` 中标记"已转化"

### 2.5 连接衰减（用进废退）

```python
def decay_unused_edges(self):
    """每 N 个 tick，衰减长时间未共同激活的边"""
    # memory_relations: 7 天未共同激活 → weight -= 0.1
    self._exec("""
        UPDATE memory_relations 
        SET weight = MAX(0.1, weight - 0.1)
        WHERE last_co_activated < datetime('now', '-7 days')
        AND weight > 0.1
    """)
    # typed_entity_relations: 30 天未共同激活 → weight -= 0.15
    self._exec("""
        UPDATE typed_entity_relations
        SET weight = MAX(0.1, weight - 0.15)
        WHERE last_co_activated < datetime('now', '-30 days')
        AND weight > 0.1
    """)
```
