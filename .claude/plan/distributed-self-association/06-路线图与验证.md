# 路线图与验证 — 从地基到涌现

## 阶段划分

```
Phase 0 ─── 地基 (已存在)
    ├── Entity hub 图结构 ✓
    ├── LLM 实体提取 ✓
    ├── LLM 关系推断 ✓
    ├── 激活扩散算法 ✓
    ├── 实体去重 ✓
    └── 事件记忆 ✓

Phase 1 ─── 持续激活引擎 (1-2天)
    ├── ActivationField 数据结构
    ├── 激活注入（store/search 时）
    ├── Background Ticker（后台节拍器）
    ├── 一步扩散传播
    └── SQLite 持久化

Phase 2 ─── 赫布学习 (2-3天)
    ├── 边权重动态强化
    ├── emergent_relations 萌芽关系表
    ├── 自动建边（共现 >= 5 次）
    └── 连接衰减（用进废退）

Phase 3 ─── 唤醒阈值与涌现 (2-3天)
    ├── 个性化唤醒阈值
    ├── EmergenceEvent 涌现事件
    ├── ConsciousnessStream 意识流
    ├── 短期工作记忆整合
    └── 子conscious prompt 注入

Phase 4 ─── 稳态平衡 (1-2天)
    ├── 全局激活预算
    ├── 艾宾浩斯遗忘曲线
    ├── 核心记忆标记
    ├── 激活风暴防护
    └── 定期维护任务

Phase 5 ─── API 与前端 (2-3天)
    ├── 激活状态 API
    ├── 涌现事件 API
    ├── 萌芽关系 API
    ├── 图谱可视化增强
    ├── 意识流面板
    └── Hermes webhook 集成

总计：约 8-13 天
```

## 依赖关系

```
Phase 1 ──→ Phase 2 ──→ Phase 3
   │                       │
   └───────────┬───────────┘
               ↓
          Phase 4
               ↓
          Phase 5
```

- Phase 1 是后续所有阶段的基础
- Phase 2 依赖 Phase 1 的激活场
- Phase 3 依赖 Phase 1+2 的激活和边权重
- Phase 4 可以 Partial 并行（预算机制独立）
- Phase 5 依赖前面所有阶段的数据

## 核心验证指标

### 定量指标
| 指标 | Phase 1 | Phase 2 | Phase 3 | Phase 4 |
|------|---------|---------|---------|---------|
| 后台 tick 间隔 | 1s | 1s | 1s | 1s |
| CPU 占用 | <1% | <2% | <2% | <3% |
| 激活持久化延迟 | <100ms | <100ms | <100ms | <100ms |
| 涌现事件 → 对话可见 | — | — | <1s | <1s |
| 记忆可唤醒性衰减 | — | — | — | 符合曲线 |

### 定性验证（通过对话观察）
1. **持续记忆测试**：连续几天和猫猫对话，观察是否能"记住"几天前的关联
2. **关联涌现测试**：频繁提及两个概念（如"分布式"和"自关联"），观察系统是否自发关联它们
3. **遗忘测试**：一个月不提及某话题，观察相关记忆是否自然"淡出"但可通过精确搜索找回
4. **压力测试**：一次性导入大量记忆，观察激活场是否稳定

## 回滚策略

每个 Phase 都是可逆的：
- Phase 1：停止 ticker 线程，删除 activation_state 表
- Phase 2：重置边权重为初始值，删除 emergent_relations 表
- Phase 3：清空 emergence_events 表，移除 subconcious 注入
- Phase 4-5：移除对应代码和 API

回滚不影响现有的 mem0 记忆和图数据库。
